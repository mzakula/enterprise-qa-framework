# AI-generated test cases

## Purpose
Capture, review, and track test cases produced by AI assistants (for generation, triage, and automation). This file documents prompts, examples, and mappings to automated specs.

## Scope
- UI tests (Playwright)
- API tests
- Database validation tests
- Negative, boundary, and risk-based scenarios

## Sources & Prompt Templates
- Prompt: "Generate UI test steps for successful login given an existing user; include preconditions and expected result."
- Prompt: "List negative and boundary test cases for the product search API, describing request, inputs, and expected status codes."
- Prompt template (generic):

```
Given system: <system-description>
Goal: <test-goal>
Constraints: <constraints>
Format: Provide test cases with ID, Title, Type, Priority, Preconditions, Steps, Expected Result
```

## Generated Test Cases (examples)

### TAI-UI-001 — Login with valid credentials
- Type: UI / Regression
- Priority: High
- Preconditions: Test user `qa_user@example.com` exists
- Steps:
	1. Open `/login`
	2. Enter valid email and password
	3. Click `Sign in`
- Expected: Redirect to dashboard and display welcome message

### TAI-API-002 — Search API: empty query boundary
- Type: API / Boundary
- Priority: Medium
- Request: `GET /api/products?query=` (empty)
- Expected: `400 Bad Request` or empty results array (depending on contract); assert response schema
- Automation: [tests/api/products-api.spec.js](tests/api/products-api.spec.js)

### TAI-DB-003 — Purchase flow: inventory decrement
- Type: DB / Integration
- Priority: High
- Preconditions: Product X stock = 1
- Steps:
	1. Place order for Product X via UI or API
	2. Verify order success
	3. Query DB for product stock
- Expected: Stock decremented to 0
- Automation: [tests/integration/api-db-validation.spec.js](tests/integration/api-db-validation.spec.js)

## Automation Mapping
- UI proofs live under [tests/ui](tests/ui)
- API specs under [tests/api](tests/api)
- Integration/DB checks under [tests/integration](tests/integration)

When promoting a generated case to automated, add the test file path in the `Automation` field and create/commit the corresponding Playwright spec.

## Review Checklist
- Verify Preconditions are actionable (DB seed or fixtures)
- Confirm expected results are deterministic
- Add tags: `smoke`, `regression`, `flaky` as appropriate
- Assign owner for manual review before automation

## How to run relevant tests
Run Playwright tests locally:

```bash
npx playwright test tests/ui/login.spec.js
npx playwright test tests/api/products-api.spec.js
```
